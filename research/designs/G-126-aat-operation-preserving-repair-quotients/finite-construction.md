# G-126：有限表からの構成と費用

[設計の入口](README.md)のDを実装する手続きと、一般定理への接続を定める。
`n = |S|`、`m = |E|`とする。返す下端・上端をAの`generated`・`behavior`と同定し、
Bの存在条件から成功・失敗の意味を導く。

## 1. 入出力と実行方法

入力は状態`Fin n`、操作名`Fin m`、遷移表`m × n`、観測表`n`、要求のBool表`n × n`とする。
観測値は任意の`O`と`DecidableEq O`を持つ。一般の有限入力との接続には、与えられた
重複のない列挙からの番号対応を使い、表の各点が元の`T,o,R`に一致すると証明する。

表はサイズ条件付きの配列で実装し、添字ループは`Fin`の明示列挙を使う。
表参照・更新、添字・Boolの演算、観測値の等号判定を数える。
表の初期化・コピーと語のセル生成も数える。RAM型のGOALの単位費用に対する上界を示し、
Leanランタイムの実時間の上界には読み替えない。

費用付きプログラムの値成分を実行関数とする。例えば`Costed α := α × Nat`と
費用を加算する合成・有限ループを使い、`runRepair := (runRepairWithCost input).1`とする。
各原始表操作に費用を与え、実行結果・停止・費用はこの一つの定義から証明する。
計算から独立した多項式を費用として返す定義にはしない。

共通の出力に両端の分割を持ち、結果は次の二択とする。

- 成功：下端・上端それぞれの有限商表、全射表、降下した操作・観測、下端から上端への写像。
- 失敗：入力の要求表にある状態対`(x,y)`と、それを観測で分離する語。

入力構造の証明fieldは表サイズ・番号対応・等号判定等に限る。
修復可能性、分離語、完成した商、正確性を入力で受け取らない。
出力の性質は表操作から証明する。

## 2. 下端：操作合同の生成

`L₀`を対角と`R`の和とし、Bool関係の更新を次で定める。

```text
closeStep(L) = L ∪ Lᵒᵖ ∪ (L ∘ L) ∪ ⋃e (T_e × T_e)(L)
L_{k+1} = closeStep(L_k)
lower = L_{n²}
```

一回の更新では元の`L`を読取り専用にする。出力表へ`L`をコピーし、
対のループで逆関係、三つ組のループで関係の合成、`e,x,y`のループで操作の像を書き込む。
更新途中の出力表を次の推論の入力にはせず、上の同期更新と実装を一致させる。

証明は次の不変条件と終了条件を使う。

1. `L_k ⊆ L_{k+1}`、`R ⊆ L_k`、対角が`L_k`に入る。
2. 任意の`R`を含む操作合同`c`について、帰納的に`L_k ⊆ c`。
3. 厳密な増加は対の有限集合の濃度を増やす。候補対は`n²`個なので、
   `n²`回の更新後には固定点になる。一度固定すれば以後も固定する。
4. 固定点は対称性・推移性・操作安定性を持つ。2と生成の最小性から
   `lower = generated T R`を得る。

一回の費用は`O(n³ + (m+1)n²)`、全更新は
`O(n⁵ + (m+1)n⁴)`である。`n=0`では空表をそのまま返す。

## 3. 上端：分離語の探索

各対に`Option (List (Fin m))`を持つ表`W_k`を作る。
`some w`は具体的な分離語、`none`はその段階で分離語が見つからないことを表す。

```text
W₀(x,y) = if o(x) ≠ o(y) then some [] else none
W_{k+1}(x,y) =
  W_k(x,y)がsomeなら、そのまま保持
  それ以外は、番号順で最初のeについて
    W_k(T_e x, T_e y) = some wならsome (e :: w)
  そのようなeがなければnone
N = n² - 1                 -- Natの切り捨て減算
upper(x,y) = (W_N(x,y) = none)
```

ここでも一回の更新は前の表だけを読み、別の表へ書く。
語は実行順に並び、`e :: w`は最初に`e`を実行する。
帰納法により次を同じ`W_k`について示す。

- `W_k(x,y) = some w`なら、`w.length ≤ k`であり、`w`は対を分離する。
- `W_k(x,y) = none`と、長さ`k`以下のすべての語の後で観測が一致することは同値。

任意の分離語を短くできることは、対状態の遷移
`(x,y) ↦ (T_e x,T_e y)`について証明する。
最短の分離語が`n²`以上なら`DFA.evalFrom_split`で非空loopを除けるため矛盾する。
DFAの開始状態は証明対象の対とし、受理集合は観測が異なる対とする。
対がある場合だけこのDFAを作るので、空の`S`に開始状態を要求しない。

したがって`n>0`では長さ`N`までの検査で全語を尽くしたことになり、
`upper = behavior T o`と、保存したすべての分離語について`length < n²`を得る。
`n=0`の場合は対がなく、同じ上端の等式が成り立つ。
各pairの短い語を直接保持するため、復元時の停止性を別の探索に委ねない。

各roundで高々`n²m`回の後続参照を行い、round数は高々`n²`。
既存の語は共有し、新たな語は先頭の一セルを加える。新規登録は各対につき一回。
表コピーを含む費用は`O((m+1)n⁴ + n²)`、最終的な失敗語の出力は`O(n²)`で抑える。

## 4. 判定・商表・一般定理との一致

元の要求表の各`(x,y)`を調べ、`W_N(x,y) = some w`ならその対と語を返す。
なければ`R ⊆ behavior`なので、Bの存在条件により成功する。
失敗が返れば元の要求対が`behavior`に属さず、Bにより修復商は存在しない。
不存在なら要求表にそのような対があるので必ず失敗を返す。

下端・上端のBool表からそれぞれ、次の番号付き分割を作る。

1. 状態`x`ごとに、関係する最小の番号を探して`rep(x)`とする。反射性から必ず見つかる。
2. 異なる代表元を昇順に列挙し、その位置をclass IDとする。
   商状態を`Fin k`として`q : Fin n → Fin k`と代表元表`section : Fin k → Fin n`を返す。
3. `q (section c) = c`、`q x = q y ↔ lower/upper(x,y)`を証明する。
   `n=0`では`k=0`であり、任意の既定状態を作らない。

分割の表は成功・失敗のいずれでも構成できる。
成功時には操作安定性と観測核への包含を証明できるので、各商について

```text
Tbar(e,c) = q(T_e(section c))
obar(c)   = o(section c)
lowerToUpper(c) = q_upper(section_lower c)
```

を表として計算する。これらの可換式は核一致から証明する。
`Setoid.quotientKerEquivOfRightInverse`に実際の`section`を渡し、
番号付きの商と数学的な`S / generated`、`S / behavior`の同型を作る。
操作・観測と商写像の可換式も同じ同型について示す。
代表元の番号に依存する表示の違いは、この`S`上の同型で比較する。

成功判定は`R ⊆ behavior`を調べれば足りるが、
返した下端が`generated`であり`generated ≤ behavior`となる証明も結果に結びつける。
費用を計算しやすくするため、代表元探索・class ID作成は素朴な二重ループとし、
商の表生成を含めて`O((m+1)(n+1)²)`とする。

## 5. 同じ実行定義についての費用証明

`runRepairWithCost`を構成する各ループについて、長さと一回の費用から上界を証明する。
入力を読み終えた後に別の意味論的関数を呼んで商や語を取り直さず、
§2–4で生成した表をそのまま出力する。

| 部分 | 上界の形 |
| --- | --- |
| 初期表と入力の走査 | `O((m+1)(n+1)²)` |
| 下端の同期閉包 | `O(n⁵ + (m+1)n⁴)` |
| 上端と分離語 | `O((m+1)n⁴ + n²)` |
| 分割、成否判定、商表または失敗出力 | `O((m+1)(n+1)²)` |

まず固定された自然数定数`C`で
`cost(runRepairWithCost input) ≤ C * (m+1) * (n+1)^5`を証明する。
`C`は入力、観測値、等号判定の結果に依存しない。
この一様な不等式から、GOALの最悪時Big-Oを導く。
表更新を関数の入れ子の更新で表して線形探索が隠れる実装は使わない。
配列操作・コピー・共有したListのセル生成を費用モデルの原始操作へ対応させ、
観測値の等号判定一回を一単位とするGOALの条件を保持する。

## 6. Law・経路入力の前処理

EのLaw族では、明示されたLaw列挙で値の依存積の等号を判定する。
Dの費用モデルは観測値の等号一回を単位とするため、
Lawの各成分比較まで数える場合には一回あたり高々`|L|`回の比較として別途換算する。
値型を有限にしたり、Lawを有限個のBool判定で近似したりしない。

経路対リスト`P`では、各元の各状態への作用を評価し、対応する要求表のセルをtrueにする。
この前処理は`O(n² + n * Σ_(p,q)∈P (|p|+|q|+1))`で実装できる。
その後でDの手続きを呼ぶ。Dの`n,m`だけによる上界は、
任意長の経路や任意個数のLawを読む費用まで含む主張へ拡張しない。

実装の接続定理は、前処理で作る表がGOALの`R_P`と一致すること、
成功出力が全経路等式と全Lawの降下を満たすこと、失敗出力がその不存在を示すことを含む。
