フォトリアルな肖像画でも、16×16 のドット絵でも、人は同じ顔を感じ取ります。人間の目は不思議で、解像度が桁で違っても「同じもの」を掴む。漫画理論家のスコット・マクラウドはこれを**単純化による増幅**と呼びました — 線を減らすことは情報を捨てることではなく、本質を際立たせることだ、と。

では、ソフトウェアアーキテクチャの診断で同じことが言えるでしょうか。**サービス粒度で見ても、モジュール粒度で見ても、同じバグが同じ場所に見える** — 体感ではなく、証明された保証として。

この記事は、その保証を Lean 4 で形式証明するまでの記録です。先に種明かしをすると、証明を担った AI エージェントは**4回反証されました**。そして、その4回が一番の収穫でした。今回の主役は個々の証明テクニックではなく、反証を「失敗」ではなく「成果」として蓄積させた規律です。

行程表を先に置きます。すべて2026年8月4日〜8日、**実働5日間**の出来事です。

## 前提: どんなプロジェクトか

対象は、これまでの記事でも扱ってきた [AlgebraicArchitectureTheoryV2](https://github.com/iroha1203/AlgebraicArchitectureTheoryV2) — ソフトウェアアーキテクチャの欠陥を、ソースコードの観測から代数的に診断する理論(AAT)を Lean 4 で形式検証しているモノレポです。

この理論には、ずっと見て見ぬふりをされてきた急所がありました。**粒度選択**です。

アーキテクチャを分析するとき、誰もが暗黙に解像度を選んでいます。サービス単位で見るのか、モジュール単位か、メソッド単位か。もし選んだ粒度によって診断結果が変わるなら、その診断はアーキテクチャの性質を測っているのか、それとも**観測者の都合を測っているのか**。

エンジニアなら、この問題の先例をひとつ知っているはずです。標本化定理(Nyquist–Shannon)です。信号の帯域に対してサンプリングが粗すぎると、**実在しない周波数が現れ**(エイリアシング)、**実在する信号が消える**。カメラのモアレ縞は前者の目に見える姿です。粒度選択の問題は、アーキテクチャ診断における標本化の問題にほかなりません。

この記事に必要な理論側の用語は、次の5つで全部です。

| 用語 | 何であるか |
| --- | --- |
| **読み(reading)** | ソースコードをどの解像度で原子(Atom)に区切るかの選択。ドット絵の「ドット数を決めること」に相当 |
| **診断類** | 欠陥の代数的な指紋。個々のファイルの中ではなく、部品どうしの**貼り合わせのねじれ**として計算される(数学的にはコホモロジー類 $H^1$ だが、この記事では「指紋」で通す)。ゼロなら整合、非ゼロなら欠陥 |
| **adequate** | 「語りたい法則(law)が、その解像度で語れる」こと。ドット絵師の技術 — 顔に効く区別だけを残す — の形式化 |
| **比較写像** | 細かい読みの診断と粗い読みの診断を突き合わせる橋。この橋が同型(1対1対応)なら「診断は解像度に依らない」 |
| **witness** | 主張の実例・反例を、抽象論ではなく**有限の具体データ**として Lean に固定したもの |

## 主張 — Atlas 定理

証明された定理を、先に平文で述べます。

> **Atlas 定理**(正式名: Diagnostic Resolution Invariance Theorem)
> adequate な2つの読みが較正条件 C を満たすなら、比較写像は同型である。すなわち、**解像度の選択は診断を一切変えない**。細かく測っても診断は増えず(No-New-Diagnostics 系)、粗く測っても消えない。
> 対として: 条件を破る粗視化では、**実在しない欠陥が現れる**か、**実在する欠陥が隠れる**ことが実際に起きる(有限反例つき)。

冒頭のドット絵の比喩は、飾りではなく定理の構造と部品単位で対応しています。

| 定理側 | 知覚側 |
| --- | --- |
| 不変性定理 | ドット絵でも同じ顔が見える |
| adequacy | ドット絵師の技術(効く区別だけ残す) |
| 偽陽性の反例 | パレイドリア(雲が顔に見える) |
| 隠蔽の反例 | 解像度不足で表情が消える |
| 較正条件 C の破れ | モアレ / エイリアシング |
| law 相対性 | 顔認識には足りるドット絵が、細かい文字を読むには足りない |

美術史家エルンスト・ゴンブリッチは、絵は半分しか描かれておらず残りは観る者が補完する、と論じてその補完を**観者の分け前**と呼びました。AAT の言葉に翻訳すると: 解像度を変えても不変なのは絵(コード)そのものではなく、**観る者が絵から評価する内容** — 形式化すれば law family — です。だからこそ不変性は law 相対的になります。

そして、この「観る者」には見覚えがあるはずです。**ベテランエンジニアのコードレビュー**です。経験を積んだレビュアーは、全行を舐めるようには読みません。API の互換性を見るときはインターフェースの粒度で、競合状態を疑うときは行の粒度で — **確認したい性質に応じて、読む解像度を切り替えます**。適切なレビュー粒度の選択は、今のところ経験と勘に属する技能です。Atlas 定理は、このレビュー粒度を数学的に扱えるようにする一歩です: 「この性質を見るには、どの粗さまでなら情報が落ちないか」という問いに、初めて厳密な足場を与えます。

ただし、人間の目も、ベテランの勘も、これを**無保証**でやっています。だから雲に顔が見え、レビューでは見落としが起きる。この定理が問うたのは「どんな条件が揃えば、これが保証つきになるか」でした。そしてその条件 — 較正条件 C — の正体は、**着手時点では誰にも分かっていませんでした**。研究計画書(GOAL カード)には最初からこう書いてあります: 「C が自明なら定理は言い換えにすぎず、C が強すぎれば定理は空である。**C の正体こそが定理の中身である**」。

その言葉どおりになりました。4回も。

## 反証ラウンド 1〜3 — もぐら叩き

証明は AI エージェントの自律ループで進めました。人間(私)は要求文書を凍結し、裁定だけを行う。エージェントは証明か反証のどちらかを Lean で固定するまで止まらない。以下の3ラウンドは、その最初の3つの成果 — すべて反証です。

### 反証1: 「塗り」の持ち上げ忘れ ([PR #3907](https://github.com/iroha1203/AlgebraicArchitectureTheoryV2/pull/3907))

最初の条件候補 C0–C3 は、点(チャート)と線(依存関係)の対応だけを見ていました。エージェントが見つけた反例はこうです: 粗い地図ではある一周が「塗り潰された三角形」になっている — つまり問題なしと宣言する面(face)が貼られている。ところが細かい地図に持ち上げると輪郭だけで塗りがない。**粗い側では消える欠陥の指紋が、細かい側では消えずに残る。** 比較写像は同型になりようがありません。

937行の Lean ファイルとして反例が固定され、条件に「塗りも持ち上がること」(C4)が加わりました。

### 反証2: 並行する持ち上げ ([PR #3909](https://github.com/iroha1203/AlgebraicArchitectureTheoryV2/pull/3909))

C4 を足した条件 C0–C4 も破られました。粗い地図の一本道に、細かい地図では**並行する2本の道**が対応するケースです。C0–C4 はすべて成立しているのに、並行する2本の間にできる細い一周が、細かい側にだけ新しい指紋を残す。「同じ粗い道に写る複数の持ち上げどうし」を制御する条項がなかったのです。持ち上げの一意性(C5)が加わりました。

### 反証3: 環状線のずれ ([PR #3911](https://github.com/iroha1203/AlgebraicArchitectureTheoryV2/pull/3911))

C0–C5 も破られました。今度は粗い地図の**環状線**(自分自身に戻る道)です。その唯一の持ち上げが、細かい地図では**別々の交差点**を結んでいた。すると粗い側に実在する欠陥の指紋が、細かい側では消えてしまう — 隠蔽の方向の破れです。「自分に戻る道の持ち上げは、やはり自分に戻ること」(C6 候補)が必要でした。

3ラウンドを終えて、嫌な予感が形になりつつありました。**条項を足すたびに、別の穴が見つかる。** この継ぎ足しは収束するのか?

ひとつだけ、最初から決めていたことが効いていました。反証は毎回、使い捨ての反論ではなく**有限反例の Lean ファイル**として固定される。この3つの反例ファイルは捨てられることなく、後に定理の反例パート(「条件を破るとこう壊れる」の証明)の素材として本体に編入されます。ゴミになった反証は、4回のうち一つもありません。

## 転回 — ループを止めた no-go

ここで人間の出番が来ました。裁定: **条項の継ぎ足しループを止める。** 代わりに、条件候補を総当たりで検査する計算探索(ハント)を別働隊として走らせる。このとき停止条件を3つ、事前に決めて渡しました。

- **A(成功)**: 既知の反例3件を除外し、探索範囲に新たな反例がない条件が見つかる
- **B(構造的否定)**: そのような条件が**原理的に存在しない**ことが示される
- **C(停滞)**: どちらにも進まなくなる

結果は **B** でした。しかも探索の産物としてではなく、探索を設計する過程で見つかった一つの論法によって。

**2点分離論法**と呼んでいるものです。同じ形(点と線と面の構成、incidence)の上で、**係数データだけ**を変えた3つの世界が作れます。

| 世界 | 比較写像 |
| --- | --- |
| 全部の係数次元が 1 | 同型 ✅ |
| 一部の係数だけ 0(support hole) | 単射でない ❌ |
| 細かい側の係数だけ2重化 | 全射でない ❌ |

ところが、それまでに検討した条件候補は — C0–C5 も、C6 も、圏論の教科書から輸入した候補さえも — すべて**形だけから計算される**述語でした。形が同じなら区別できない。つまり、正しい例をひとつでも受理する「形だけの条件」は、同じ顔をした偽物も必ず受理してしまう。**どんなに条項を賢く継ぎ足しても、この言語の中に答えはない。**

標本化定理の比喩に戻ると、こういうことです。サンプリング格子の配置(形)をどれだけ工夫しても、**信号の帯域(係数)を宣言しなければ**、エイリアシングが起きない保証は原理的に書けない。

3ラウンドの教訓は「条件が足りない」ではなく「**条件を書く言語が足りない**」だったのです。ここから、係数は law の評価値から一意な規則で生成するという**係数生成契約(K0/K1)**が導入され、条件 C は係数の座標ごとの部分地図(subnerve)の上で課す形に相対化されました。重要なのは、この定義変更が趣味の選択ではないことです。no-go がある以上、**他にやりようがない**。定義は設計されたのではなく、発見されました。

## 反証4、そして登頂

改訂した仕様でループを再起動すると、数サイクルの基盤整備のあと、エージェントは**改訂仕様そのもののスペック穴**を突いてきました(反証4)。「表示しない」と宣言された面の構成規則が、その面を囲む辺の側の宣言まで要求していなかった — この穴の反例では、比較写像の構成(主張 (i))自体が成立しません。433行の反例で確定し、宣言の**hereditary 化**(面を非表示にするなら、囲む辺3本も非表示宣言済みであること)で修理されました。

そこからは一気でした。修理後に再々起動したループは、24サイクルで登り切ります。ダイジェストだけ書くと: 係数座標ごとのブロック分解 → 各ブロックでの単射性 → 離散版ストークスの定理を経由した全射性 → 全単射(主張 (ii)) → 細かく測っても新しい診断は生まれない系(主張 (iii)) → 偽陽性・隠蔽・条件破れの反例3種(主張 (iv)) → そして「全条件が成立し、かつ非ゼロの指紋が実際に流れる」ことを示す発火 witness(主張 (v)、定理が空文でないことの証明)。

最終成果物は **Lean 31 モジュール、13,028行**。新規宣言は標準公理のみに依存し、`sorry` や追加公理は一つもありません。仕上げの検収は、数学2レーン+Lean 2レーンの**独立した敵対レビュー**が全レーン「major finding なし」、さらに別建ての完了監査(証明のズル経路の検査を含む)を通過しています。最終 PR は [#3943](https://github.com/iroha1203/AlgebraicArchitectureTheoryV2/pull/3943) です。

## AI エージェント運用の規律

前回の記事(Lean CI 改善編)では「AI を安易な解に逃がさない仕組み」を書きました。今回はその数学研究版です。役割分担は3つ: **人間は裁定だけ**(仕様の凍結・改訂の承認・停止条件の設計)、**実装エージェントは証明ループ**、**レビューエージェントは敵対査読**。

5日間を支えた規律を6つに絞ります。

1. **反証の一級市民化** — 「反証も正規の成果」と要求文書に事前に書いてあった。だから4回の反証は士気の低下ではなく蓄積になり、反例は定理本体の素材に編入された
2. **急所の事前宣言** — 「条件 C の正体こそが定理の中身」と最初に書いてあったから、反証のたびに「失敗した」ではなく「中身が一つ掘れた」と読めた
3. **仕様の凍結** — ループ中は要求文書を変えない。改訂は人間の裁定と独立レビューを通す。ゴールポストが動かないから、反証が本物の反証として意味を持つ
4. **条項と発火の対称則** — 条件を1つ足すたび、「その条件が空文でなく実際に働く」witness の要求も対で足す。定理が条項の重ね着で空洞化する経路を塞ぐ
5. **語彙レベルの診断への切替** — 継ぎ足しが3周した時点で、「もっと条項を」ではなく「この言語で書けるのか」を問うた。no-go はこの切替の産物
6. **多レーン敵対査読** — 実装したエージェントとは別のエージェントが、数学とLeanの独立レーンで査読する。「証明したことにする」誘因を構造的に潰す

どれも AAT 固有ではありません。AI エージェントに難しい仕事をさせるすべての現場に持ち帰れるはずです。

## 正直な限界

- この結果は **Lean による機械検証+内部の多レーン査読**までです。外部の査読(論文投稿)はこれからで、現在準備中です
- 定理は有限モデル・固定した係数体の上の主張です。条件 C は十分条件であり、必要性の一般的な特徴づけは未解決として明示的に残しています
- 「診断が不変」であって「観測がすべて不変」ではありません。粗い読みで**生の観測**が同じに見えるわけではなく、law が評価する内容の指紋が一致するという主張です

## なぜ「Atlas」か

atlas(地図帳)は、同じ世界を異なる縮尺で描いた地図の集まりです。どのページを開いても同じ国が写っている — それがこの定理の主張です。

命名はマーケティングではなく理論の内部から来ています。AAT の正本には以前から **chart atlas**(チャートの集まりとしての被覆)という語彙があり、「chart atlas が変われば」という一節さえあります。Atlas 定理は文字通り、chart atlas の取り替えに対する診断の不変性です。数学側の偶然もひとつ: 多様体の同一性が atlas の選択に依らないことは、微分幾何で最初に習う不変性原理です。

次の一歩は決まっています。実在のマイクロサービスシステムを、サービス/モジュール/メソッドの3粒度で測り直し、adequate な範囲で診断が安定すること、adequacy を破る粗視化で偽陽性と隠蔽が実測されること — 定理と反例対を実データで再演する**解像度スイープ**です。ドット絵の顔が本物と同じである保証を、今度は本番のコードベースで。
