# QA記録テンプレート

設計・実測・findingの記録時に使う。tracking Issueの既存欄を優先し、不足分だけ補う。
許可された保存先に置き、Issueへ証拠の参照を集約する。`<…>`を実際の値に置き換え、
未取得の値は理由付きで未確認と書く。見本の項目を実施済みとして扱わない。

## 候補・実行環境

```text
対象: ArchSig <version> / 候補 <full commit SHA>
リリース範囲・対象外: <合意と参照>
マニュアル: docs/tool/archsig_manual @ <参照commit>
tracking Issue / ローカル記録: <URLまたは保存先>
操作制限: <今回許可された実行と書込み>
Mac: <macOS版・build / CPU / Rosetta等の実行方式>
runtime・解析器: <名前・版>
binary: <絶対パス / SHA-256 / 実測version、取得不能なら理由>
対応根拠: <配布物の名前・digest・入手元・候補との出所、またはbuild手順・source commit・dirty状態>
インストール: <配布予定の形 / 入手・展開・導入手順 / 実測証拠、未定なら未確定・未検証>
日時・cwd: <実測日時 / 隔離領域>
```

## テスト項目

```text
ID・目的: QA-<番号> <操作と確かめること>
マニュアル節: <ファイル @ commit / 見出し、必要なら行番号>
入力・前提: <fixture内容・digest / 初期状態 / 依存する項目>
コマンド・cwd・環境設定: <正確な再現手順>
期待結果・根拠: <stdout/stderr・終了コード・生成物等 / マニュアルから導いた条件>
観測方法: <取得するログ・生成物・比較方法>
対象外: <今回この項目で判定しないこと>
状態: <未実施 / 合格 / 不合格 / 中断 / 実施不能 / 人間判断待ち / 実測完了・人間判定待ち / 実測完了・人間判定済み>
実測: <候補SHA / binary digest / 日時 / stdout・stderr・exit code / 生成物と変化>
証拠: <再読可能なログ・生成物の保存先とdigest>
finding・判断: <F-ID / 差の説明 / 人間判断への参照>
未実施・不能・中断: <理由 / 測定済み部分と未測定部分 / 再開条件>
再検証: <旧→新候補 / 再試験範囲と理由 / 利用する旧証拠の理由 / 新結果>
```

章節の対応表では `章節 | 項目ID | 対象外・項目なしの理由` を使う。
項目一覧では `ID | 候補SHA | 状態 | 証拠 | finding / 再開条件` を使う。
チェックマークだけで状態や測定済み範囲を表さない。

## Finding

```text
ID・分類: F-<番号> <既知制限 / 既知問題 / 新問題 / 仕様の曖昧さ>
関連項目・既存Issue: <QA-ID / URL、未起票なら理由>
候補・binary: <full commit SHA / version / binary digest>
環境・再現条件: <Mac / 入力・digest / 初期状態>
再現コマンド: <cwd・必要な環境設定を含む手順>
期待・マニュアル節: <確定した期待または未確定の問い / 節 @ commit>
実際との差・証拠: <stdout/stderr・exit code・生成物 / 証拠参照>
影響: <利用者への影響 / 依存して止める項目 / 独立に継続する項目と理由>
今回の範囲: <合意したリリース範囲との関係>
引渡し・再検証: <修正側の参照 / 修正候補 / 対象項目・影響範囲 / 実測結果>
状態: <未解決 / 修正候補待ち / 再検証待ち / 再検証で解消確認 / 人間判断待ち>
人間判断: <判断者・日時・対象候補・受入リスク・条件。観測結果とは別記>
```

## 結果が揺れる項目の測定

```text
計画: <QA-ID / 固定日時 / 同梱SKILLの版・digest / モデルと版 / 設定>
入力・fixture: <全文の保存先とdigest / 各試行の初期状態と準備>
予定試行数・観測方法: <N / 測る条件 / 記録方法>
試行: <試行ID / 候補・binary / 日時 / 入出力・生成物・対話ログの保存先 / 観測値>
終了状況: <完遂 / 中断 / 不能 / 未実施、理由と測定済み範囲>
観測結果: <成功 / 失敗等、基準と実測値。途中・未測定なら取得できた値と未確認部分>
集計: <予定N / 排他的な終了状況の各件数 / 観測結果別件数 / 比率を示す場合は分子・分母>
追加・変更: <理由 / 新計画への参照。旧計画と全試行は保持>
QA状態: <未完遂なら中断等の状態、完遂なら実測完了・人間判定待ち、回答後は実測完了・人間判定済み>
人間判定: <依頼する判断 / 返答があれば判断者・日時・対象候補と条件>
```

試行IDは失敗・中断も含めて残し、未実施の予定試行も列挙する。
測定を完遂して失敗結果を得た試行は「終了: 完遂 / 観測: 失敗」とし、二つの軸を混ぜない。
数値の取得が途中なら、取得した実測値だけを示す。人の判定を受けた後も生の実測値を保持する。
