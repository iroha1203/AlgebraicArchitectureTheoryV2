# 7. SKILL

ArchSig の入口は、AI エージェントの SKILL である。
人は普段使うエージェントに、目的と制約を伝える。エージェントは SKILL に従って ArchSig を呼び、結果を人に報告する。
この章では、ArchSig と一緒に配る四つの SKILL と、どの SKILL にも共通する決まりを扱う。

## 四つの SKILL

### archsig-law:Law を書く

守りたいことを、Law ファイルにする SKILL だ。

1. 人から、守りたいことを聞く。
2. コードを読み、読み、意味の語彙、Law を書く。
3. `archsig law check` で、書けているかを確かめる。
4. `archsig law diff` の結果を人に見せ、承認を受ける。
5. `archsig next` で、新しく観測が必要になった所を確かめ、archsig-observe へ渡す。

Law は強いモデルが書く。版をまたいで使う資産なので、書き直しの手間より正しさを優先する。

### archsig-observe:観測する

ArchMap を作り、今のコードに追いつかせる SKILL だ。

1. `archsig status` で、古い範囲と、読んでいない範囲を確かめる。
2. 構造 Atom は、言語ごとの解析器で取り出す。
3. 意味 Atom は、軽いモデルのエージェントに観測させる。
4. `archsig validate` で、ArchMap が受け付けられるかを確かめる。

意味 Atom の観測は、次の手順で行う。

- 同じ範囲を、二つのエージェントが別々に観測する。互いの結果は見せない。
- 二つが一致した Atom を記録する。
- 一致しなかった Atom は、強いモデルが元のコードを読んで決める。
- 観測するエージェントに渡すのは、意味の語彙と観測の手がかりだけである。Law の規則は渡さない。

観測は粗い読みから始める。`archsig check --reading <粗い読み> --against <細かい読み>` で、粗くては足りない局所が分かったら、そこだけを細かく読む。

### archsig-change:変更を進める

機能の追加や内部構造の変更を進める SKILL だ。第2章で追った流れがこれに当たる。

1. 人から、したいことと、変えたくないことを聞く。
2. 変えたくないことに当たる Law があるかを確かめる。無ければ archsig-law へ。
3. archsig-observe で、観測を今のコードに追いつかせる。
4. 変更の候補を書き、`archsig plan check` で検査する。
   沈黙したら `next` の所を観測する。反例が出たら、候補を直すか、人に仕様を聞く。
5. 決め方が複数あれば、`archsig plan choices` で数え上げ、絞るための判断を人に聞く。
6. `archsig plan split` で仕事を分け、各担当に条件を渡す。
7. 実装後、変わったソースを観測し直し、`archsig compare --plan` で候補と比べる。ビルドとテストも実行する。
8. 人に報告する。

### archsig-review:変更をレビューする

プルリクエストをレビューする SKILL だ。

1. 変更前と変更後のコミットで、変わったソースを観測する。
2. 両方で `archsig check` を実行し、`archsig diff` で差分をとる。
3. 新しく成り立たなくなった結果を、ソースの場所とともに報告する。
4. プルリクエストに候補が付いていれば、`archsig compare --plan` の結果も報告する。

## エージェントが守ること

ArchSig を呼ぶエージェントも、手間を減らす方向へ流れる。
Law を弱めれば違反は消え、観測を省けば沈黙で済む。SKILL は、この流れに次の決まりで備える。

- Law を書き換えるのは archsig-law だけである。ほかの SKILL は Law を変えない。違反が出たら、コードか候補を直すか、人に聞く。
- Law の変更は、コードの変更とは別に人がレビューする。
- 沈黙を結論として報告しない。沈黙は数と理由を添えて報告し、`next` の所を観測する。
- ArchMap に判定を書かない。ArchMap の形に、判定を書く欄は無い。
- 観測するエージェントには、Law の規則を見せない。

## 人への報告

人への報告は、次の順に書く。

1. 問いへの答え。成り立つか、成り立たないか。
2. 成り立たない所。反例は、入力の条件と二つの結果を平易な言葉で書き、ソースの場所へのリンクを付ける。
3. 人に決めてほしいこと。仕様の判断、決め方の選択、Law の承認。
4. 沈黙の数と理由。

計算の欄の名前や、Rising Sea の用語は、報告の本文に出さない。

## 解析器

構造 Atom を取り出す解析器は、言語ごとに別のプログラムである。ArchSig 本体は言語を知らない。
v0.6.0 では、Python、Java、Rust の解析器を用意する。
解析器は ArchMap の形で Atom を書き出し、ArchSig がそれを検査する。言語を足すときは、解析器を足す。
