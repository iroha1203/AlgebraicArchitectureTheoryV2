# 9. Rising Sea との対応

ArchSig の計算は、AAT の基礎論文 Rising Sea の構成と結果にもとづく。
この章では、ArchSig のどの部分が論文のどこに対応するかと、ツールの都合で変えた所を示す。
節番号は Rising Sea 初版(arXiv v1)の日本語原稿による。

## 入力と構成

| ArchSig | Rising Sea |
| --- | --- |
| Atom、ArchMap | §1.1 Atom と相対的な抽出 |
| 要素と操作、変更の候補 | §1.2 Configuration、対象、操作 |
| 読み、局所 | §1.3 局所文脈と Law、§1.7 Reading の射 |
| 局所どうしの重なり | §1.5 被覆から site へ |
| Law の規則 | §1.3 局所文脈と Law、§2.1〜2.2 Law の方程式と評価 |

ArchSig は、Atom と読みから局所と重なりを作り、その上で Law を評価する。
論文では、局所文脈の被覆から site を作り、係数を備えた幾何へ進む。ArchSig は、有限の被覆と、そこから作る有限の複体だけを扱う。

## 問いごとの対応

**Law を守っているか。** §2.2 の Law を満たす空間と評価に当たる。
`no` と `each` は、Law の方程式を、要素ごとに成り立つかどうかの判定として計算する形である。

**全体で貼り合うか。** §2.4 の Čech 障害類、§2.6 の閉路による検出、§2.8 の整数係数の具体的な障害に当たる。
流れの換算を整数で表すのは、§2.8 の局所状態とアフィン遷移の形である。
直す場所の候補は、§2.9〜2.10 の意味的な局所修復と大域的修復にもとづく。

**変更の後も保たれるか。** §4.2 の exact な変更に沿った core の構成と、§4.10〜4.11 の読取りと更新、操作と adapter の輸送に当たる。
`changes commute with operations` は、変更と操作の可換図式を、書き込みの列の上で確かめる形である。

**経路や順序で結果が変わるか。** §4.4〜4.6 の輸送の合成と比較、辺の選び直し、§5.10 の二つの経路の生成比較に当たる。
打ち消し合う変更の除去は、§6.1〜6.2 の正規化による。

**粒度を変えても診断は変わらないか。** §3.1 の標準解像度、§3.5 の条件 C による診断不変性、§3.11 の被覆の細分に当たる。

**条件を満たす変更は何通りあるか。** §7.3 の観測で見分けるための条件、§7.6 のすべての持ち上げ、§7.7 の操作のつながりによる分類に当たる。

**仕事をどう分けるか。** §2.5 の障害類の消滅から貼り合わせへ、§8.3 の分離と組立て、§8.5 の局所再構成に当たる。
§8.6 の設計変更への適用が、分けた仕事を組み立てる例である。

**次にどこを読むか。** §7.3 の観測で見分けるための条件が、候補を見分ける観測の根拠になる。
読んでいない範囲と `?` による沈黙は、ツールの側の決まりである。

## ツールの都合で変えた所

- 対象は有限に限る。Atom、要素、局所、候補はどれも有限個である。
- 係数は整数に限る。貼り合わせの障害は、整数の足し算で確かめられる形で計算する。
- 読みの形は `dir`、`file`、`groups` の三つに限る。
- Law の規則は `no`、`each`、`agrees along`、`changes` の四つの形に限る。
- 操作は、書き込みの列として表す。呼び出しの結果は、同じ操作に同じ値を渡せば同じ結果が返るものとして扱う。
- 条件は、成り立つ場合と成り立たない場合の二つの分岐として扱い、条件どうしの関係は見ない。
  そのため、実際には通らない分岐の組み合わせについても比べる。反例には、入力が満たすべき条件が付くので、通るかどうかは読み手が確かめられる。
- 数え上げには上限がある。上限を超えたら、`limit` で沈黙する。

## 結論が語ること

ArchSig の結論は、ArchMap に記録された Atom の上での計算結果である。
それが実際のコードについて言えるかは、Atom の `at` でソースへたどること、コードが変わったら観測し直すことで確かめる。
計算の結果と、コードとの対応の確認は、別のものとして扱う。

どの結果も、計算が立っている節を `theory` に持つ。
定理の条件を入力の上で確かめたものは `conditions` に並び、確かめられないものがあれば沈黙する。
