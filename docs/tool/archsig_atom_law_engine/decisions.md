# 設計判断・根拠

[設計本文](README.md)と[エンジン自身の Law](engine_laws.md)に対する判断理由をまとめる。
ここで定めるのは、計算核の構造と設計の選択である。

## 1. 設計で採る選択

| 論点 | 選択と理由 | 比較した代替案 |
| --- | --- | --- |
| 計算の出発点 | Atom と LawModule の二入力にする。対象・操作・診断まで導出の依存を追える | 完成した幾何や診断を入力すると、その構成を外部へ移し、本物の計算という要件を満たさない |
| 既存実装との関係 | 概念上独立した新しい核を設計する。v0.5.x の形式に合わせて入力を増やさない | 既存 artifact の各欄をそのまま次版の入力へ移すと、観測と導出済み情報が混ざる |
| Law の表現 | 型付き宣言と構成規則、方程式、問いを持つ DSL にする | 汎用 callback は観測値・外部状態・計算済み結論を隠し、意味の独立検査を難しくする |
| 局所性 | 自由変数・参照・作用の support から Context と Cover を作る | ファイルやサービスで先に分割すると、言語非依存性と、Law が必要とする重なりを失う |
| 計算領域 | 最初は有限関係・有理アフィン式・有理線形方程式を選ぶ | 万能な solver を先に選ぶと、原始構成・適用条件・失敗理由が隠れる |
| 数学との対応 | 成果ごとに構成する対象、射、仮定、結論の対応を持つ | 「AAT 対応」というタグだけでは定理適用を判定できない |
| 共通表現 | 対象・名前付き操作・作用・incidence・係数・導出を型付きで保持する | 単純グラフや単一スコアでは操作の差、面の関係、比較写像が失われる |
| 再利用 | 同じ二入力に根を持つ導出の継続または再検査とする | 外部結果に署名や digest があるだけでは、現入力からの導出にならない |
| 自己モデル | 仕様の型・式・参照を Atom にし、可換性・保存性を Law にする | 部品名を Atom と呼ぶだけでは、エンジンの動作要件が方程式にならない |
| 判定不能 | 情報不足・未対応算法・中断を理由として区別する | すべて零・成功・失敗のいずれかへ潰すと、得た結論の意味が変わる |

これらは [コンセプト](../archsig_v0_6_0_concept.md) の本物の計算、二入力の独立性、
対象と対応の保持、言語独立、ゼロからの再設計を具体化する選択である。

## 2. 拡張を成立させるための判断

### 2.1 有限提示と一般定理

有限の Atom から始めても、operation-closed core の対象数や操作語は無限になりうる。
最初の実装では、有限な閉包が停止する場合、または項として記号表示できる場合を扱う。
全操作語の等値や全対象の性質を、探索深さだけで決定しない。

[AAT 第VIII部](../../aat/algebraic_geometric_theory/part_8_measurement_theory.md)
定義4.1・定理4.2は、使用する係数・kernel・image・quotient 等に明示的な算法を要求する。
[第X部](../../aat/algebraic_geometric_theory/part_10_semantic_repair_descent_saga.md)
§10は、一般 SAGA 定理の有限実現として原始表示から比較条件を確認する。
この区別に従い、有限計算の結果は選択した実行可能な読みについて返す。
数学本文の一般的な対象・量化を、有限実装の都合に合わせて変更しない。

### 2.2 Atlas では二つの保存を区別する

[Rising Sea 第6章](../../../outreach/paper/rising-sea/ja/06-resolution-invariance.md)
の Law の十分性・標準商・比較写像を参照する。
Law の評価タプルが同じであることと、被覆・係数を含む診断が保存されることは別である。
粗細 reading から実際の比較を生成し、その kernel・cokernel を計算できる構造を保持する。
すべての比較に同型性を仮定してから走らせる設計は採らない。

### 2.3 SAGA では二つの側を独立に構成する

[AAT 第X部](../../aat/algebraic_geometric_theory/part_10_semantic_repair_descent_saga.md)
§§3–8に従い、意味側は生成元・関係・作用から、方程式側は equation から構成する。
同じ計算結果を二つの名前で包んで比較同型としない。
原始対応から誘導する係数写像について、kernel/image、制限との可換性を確認する。
actual repair には局所状態の対応と gluing まで必要であり、解なし／可解性の判定とは別に
具体的な修復状態を返す。

### 2.4 輸送・正規化・再構成では操作を消さない

根拠は Rising Sea の[輸送と整合性](../../../outreach/paper/rising-sea/ja/07-transport-coherence.md)、
[基底変換](../../../outreach/paper/rising-sea/ja/08-base-change.md)、
[冪等正規化](../../../outreach/paper/rising-sea/ja/09-idempotent-normalization.md)、
[局所再構成](../../../outreach/paper/rising-sea/ja/11-local-reconstruction.md)である。
対象の対応だけでなく、名前付き操作、始域・終域、configuration への作用、Law 評価、
局所制限を保持する。普遍性は完成した universal map を入力するのでなく、
対応済みの有限形式なら候補の存在・一意性を計算し、それ以外は構成則と証明を追加する。

## 4. 設計を具体化するための確認例

実装する場合は、次のまとまりごとに意味と受け入れ条件を確定する。
[三操作の局所・大域計算](local_global_example.md)と
[L05の具体的評価](compiler_preservation_example.md)は、
そのための仕様モデルと独立検算を与える。以下は処理系実装に課す確認項目である。

1. **原始入力から方程式へ。** 本文§6の三操作を、同じ Law の下で不成立・成立・不足値の
   三例にする。反例、行列、解を核が生成し、手計算と一致することを確認する。
2. **同じ意味の別表現。** ID・並び順・source ref・言語名を変える。値と関係を固定した
   同型に沿って、判定・解集合が対応することを確認する。
3. **入力の責務。** 完成済み判定、手書き cover、結果参照、外部 callback、対象固有の
   Law 定数を混ぜた例で、どの提示規則に反するかを確認する。値に結論を偽装した例は
   自動検出保証の対象にせず、語彙と観測の点検例として扱う。
4. **対象と射。** 同じ端点の異なる操作、非可換な二経路、削除を含む変更の span を用い、
   Atom map と Law 保存の検査が別々に働くことを確認する。
5. **局所から大域へ。** 係数と制限から微分を作り、具体的 cocycle、零類の補正、
   未決の層条件を区別する。有限 Čech 計算を sheaf cohomology と同一視する場合は
   Leray／acyclic cover 等の接続条件を別途確認する。
6. **比較と修復。** Law 評価は保存するが診断は保存しない例、意味と方程式の比較条件が
   成立する例・成立しない例、局所解だけでは全体解にならない例を揃える。
7. **自己モデル。** コンパイル前後の式、導出根、制限・合成を参照評価で照合する。
   自己検査の成功を入力 Atom に再投入して正しさを主張する循環がないことを確認する。

CLI、終了コード、再利用、出力の永続化はI/O仕様に従う。
処理系の内部実装はその入出力の意味を保つように構成する。
