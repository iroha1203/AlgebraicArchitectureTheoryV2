# 決定理由

## 1. 統一した選択

| 論点 | 決定と理由 | 退けた代替案 |
| --- | --- | --- |
| ArchMap | JSONのsnapshot・subject・単一値predicate。多値は型付きSet/List | 値の無い行を空関係にする形式は、欠測と不在を混ぜる |
| Law具体構文 | JSON宣言＋型付きprefix arrayの一つだけ | 独自テキストとJSON ASTの併設は、二つの文法と意味の同期を必要とする |
| 語彙 | Law moduleでsort/data/predicate/pureを先に宣言しdigestを固定 | 言語固有parserやcallbackを核へ渡す方式は、意味と導出根を外へ出す |
| 型 | 原始型、導出型、検査済み型を分離。環はModule等の型引数に保持 | 名前だけのJSON objectやuntyped graphでは、写像の端点と係数の違いを保持できない |
| 欠測 | 原始slotをidentityに持つHole。未知guardを保持 | 未観測を零、偽、空集合へ変換すると、存在した操作を消し反証の意味を変える |
| 対象と操作 | 原始familyを固定し、関係・識別・値作用を別に導出。名前付き語は順序を保持 | 端点の組だけのedgeや操作集合は、平行操作と非可換な経路を失う |
| Contextとcover | 原始supportの閉包から生成。一般chartはContextPointとContextMapで表す | ファイル分割や完成coverの入力はLawが必要とする重なりを計算しない |
| 係数 | Q、Z、Fpの正確な有限表示。式としては非線形presentationも保持 | Qへの暗黙変換はtorsionを失う。任意環の完全solverを約束することも採らない |
| 核の範囲 | 有限関係・有限ADTのfold・線形代数・有限提示された操作core | 有限深さの探索だけで無限の語問題を決定したとする扱いを採らない |
| 候補 | ArchMap内のproposed snapshotと原始対応。保存は核が検査 | RepairPlanや検査済み射を第三入力にする方式は答えを受け取ってしまう |
| 十分性と保存 | Law評価のfiber検査と、実cochain写像・核・余核・指定類の対応を分離 | Law値が一致したという理由だけで診断の同型を付けない |
| 標準商 | 商の元はSet(T)の同値類、商写像は有限StateMap | 評価値を商の元にするとLawValuesの外延比較とSet適格性を混同し、専用商型は追加の射影を必要とする |
| pureの全域性 | closureはderive専用、set式は重複除去 | 有限universe外を黙って切り捨てる意味変更や、適型pureに失敗を残す方式を採らない |
| 操作の端点 | configurationのidentityと状態carrierを構成時に照合 | 保存が正しい別対象のhom/作用を取り付けても、指定Architecture間の操作にはならない |
| 修復 | 解集合→局所作用→補正→貼り合わせ→元の式への再代入 | 障害空間の次元だけを修復可能性に読み替えない |
| 次の計算 | 同じDSLで型付き意味値を参照。特解・基底・statusは外部表示 | テキスト再解釈と便宜的な証人選択を、後続Lawの意味にしない |
| 追加観測 | Holeの依存を返し、明示有限候補族では識別対と包含極小族を計算 | 未指定の観測宇宙に対する最小性を名乗らない |
| 自己モデル | 原始AST/規則/型を同じdataで記述し、foldによる独立解釈を比較 | 自己検査の成功をAtomへ戻す循環、compiler例専用inputを採らない |
| 再利用 | 現在の二入力から推論を再検査、または再計算 | digest・署名・verifiedラベルだけで外部結論を採用しない |
| 外部動作 | check/run、単一result、状態と理由、原子的出力を先に固定 | 実装ごとにexitや欠測表現を補うと、利用者間で異なる読みになる |

## 2. 能力と保証

有限で完全な対象、全有理数代入のアフィン等値、Q/Z/Fpの有限線形問題は必須の決定範囲とした。
無限のcoreは有限の生成元と語として保持し、一般の商等値は未対応として式を返す。
表現できるが判定算法を持たない対象を、表現自体から取り除かない。

一般chartの二つの射、整数torsion、面の反復incidenceは、現在の三操作例を越えて
必要な構造である。ContextMap、係数型、Listによる操作語と線形和がそれぞれ保持する。
新しい個別デモ用の書式を追加せず、同じ値型・構成演算へ接続する。

原始Termの意味を固定するため、語彙bindingはpure定義も含む。
同じschemaで関数名だけを残して本文を変更する方式は、再観測が必要な意味変更を隠すため採らない。

## 3. 既存設計の論点の決定先

[旧設計の論点](../archsig_atom_law_engine/decisions.md)の具体構文・語彙・Context生成・coverage・
演算領域・記号的core・候補・最小観測・自己Law・再利用・外部artifactは、上表の各項に対応する。
本仕様の中に通常の設計選択の保留欄は置かない。

未実装と未証明は [検証](validation.md) および [数学への接続](math_obligations.md)で明示する。
それらは入力欄や外部動作を実装時に決めるという意味ではない。
数学調査で新規Rising Sea一般定理の必須不足は特定されなかった。
新DSLの健全性、部分観測、局所生成と既存SAGAの接続は製品固有の証明義務として残す。
