# ArchSig v0.6.0 I/O 仕様

ArchSig は、Law が定める語彙・読み・構成規則を ArchMap の原始 Atom に適用し、
対象・名前付き操作・対応・局所構造・診断を型付きの導出として返す。
本仕様は v0.6.0 の実装が従う入出力を決定する。処理系の実装済み状態を表すものではない。

## 1. 読む順序と優先関係

| 文書 | 決めるもの |
| --- | --- |
| [入力](inputs.md) | ArchMap、値、参照、語彙、由来、二入力の版 |
| [Law DSL](law.md) | 唯一の具体構文、束縛、型、構成、問い、欠測の意味 |
| [計算カタログ](computations.md) | 公開演算の署名・意味・成立条件・決定範囲 |
| [実行と出力](execution.md) | CLI、出力値、導出、外部状態、再利用 |
| [決定理由](decisions.md) | 採用案、退けた案、コンセプトとの対応 |
| [検証](validation.md) | 短い完全入力、期待結果、反証的な点検、実装時の適合確認 |
| [数学への接続](math_obligations.md) | 既存結果と製品側の証明義務 |

根拠は [製品コンセプト](../archsig_v0_6_0_concept.md)、
[入力の責務](../guideline.md#責務範囲入力トライアドの正本)、
[Atom と Law のエンジン設計](../archsig_atom_law_engine/README.md)である。
後者の設計記法を本仕様の具体構文に置き換える。既存設計の「未決事項」は
本仕様の決定理由に対応づける。v0.5.x の形式・CLI・互換性・移行を本仕様へ持ち込まない。

規範語「必須」「拒否」「返す」は実装要件である。表の署名と意味は規範であり、
例と検算はその確認に使う。未掲載の構文、暗黙変換、プラグイン演算は v0.6.0 にはない。
数学的な一般対象を表現することと、個々の問いを決定することを分ける。
対応する算法がない有効な問いは、型・入力・要求した命題を保持して `unsupported` を返す。
対応済みの有限計算を常に沈黙させる実装は適合しない。

## 2. 意味上の二入力

```text
A : archsig.archmap/1     原始事実を持つ snapshot の有限族
L : archsig.law/1         語彙、構成規則、要求、問いを持つ module の有限族

(A, L, query 名の選択)
  → 型付き導出 DAG
  → query ごとの確定値・反証・理由を持つ未決定
  → archsig.result/1
```

Law を先に選び、その語彙で実装コードの使用を観測する。
ArchMap の subject ID、件数、パス、完成した分割を Law に埋め込まない。
Law の名前・数学定数・要件として先に選ぶ閾値は Law に置く。
原始の構造や式が要件に適合するかは核が計算する。
Law の適用先は ID の列挙ではなく、型と原始事実への式で選ぶ。

観測・提案・仕様モデルは A の snapshot の由来で区別する。同じ構成則を適用できるが、
提案上の成立を現状の実装についての成立に変換しない。
結果を再利用するファイルは計算の補助であり、意味の根を増やさない。

## 3. 保持する区別

- 原始値、未観測値、明示的な不在、空集合、零は異なる値・状態を持つ。
- 同じ端点・同じ作用を持つ名前付き操作も、別の操作として保持する。
- 候補写像、configuration 保存、Law 保存、診断保存は別の型・別の検査である。
- Law 評価の十分性と、cover・係数・複体を含む診断の保存は別の命題である。
- 障害空間と対象の障害類、方程式の解と意味状態の修復は別の出力である。
- 有限モデルでの確定、全代入についての記号的決定、未観測値の補完についての確定を
  出力の `scope` に保持する。

エンジン自身にも同じ A と L を用いる。構文木、原始変換規則、型、参照を Atom にし、
独立した参照解釈と生成した式の比較を Law にする。
有限な自己検査の成功は、その検査器の一般的な健全性証明と別に扱う。
