# ArchSig v0.6.0 I/O 仕様

この仕様は v0.6.0 全体の実装要件を定める。クレートのビルド・入力検査・Rust API の使い方は
[クレート README](../../../tools/archsig_v0.6.0/README.md)を参照する。
checkを含む標準出力への具体的なエラー通知と、失敗記録ファイルを作らない動作も実装要件である。

Atom 定義は観測対象・属性・関係の語彙、型、意味を定める。Law はその定義を参照して
関係・制約と読みを宣言し、ArchMap は同じ定義の語彙で観測した原始事実と由来を保持する。
ArchSig はこれらの入力から対象・名前付き操作・対応・局所構造・診断を
計算し、型と導出元を持つ結果を次の計算へ接続する。

## 1. 入力、問い、結果

```text
Atom 定義: 共通語彙・型・意味と、その依存参照
Law     : 定義参照・view・個々のlaw・local・change等をまとめた reading の宣言
ArchMap : その語彙に従う原始値・参照・式・候補対応と由来
問い    : 宣言済みの読み、調べる対象、既に導出した結果を選ぶ実行要求

(Atom 定義, Law, ArchMap) ── 問い ──> 型付き導出、値、成立・反証、理由を持つ未決
```

意味上の入力は Atom 定義・Law・ArchMap の三種類である。定義ファイルは複数の語彙を
包装でき、複数ファイルも明示指定できる。意味上の入力の種類とファイル数を区別する。
Law は必要な区別を決める意味上の設計の出発点であり、語彙と型は独立した Atom 定義が持つ。
問いは調べる命題・対象・段階を選び、値・対応表・係数・
仮定を追加しない。計算予算と出力先も実行指定である。
Law に特定の snapshot ID、subject ID、観測した値や完成した解析手順を埋め込まない。
名前、数学定数、ドメインの意味として選ぶ要件・閾値は Law に置く。

`reading` は Law 入力の再利用単位、`law` は適用・role・原式を持つ一つの条件、
`view` は型付きの読取りである。核は作者の宣言から共通の構成を作る。
作者は context、cover、行列、係数、微分、保存証拠を配線しない。

定義作者は語彙・型・意味を、Law 作者は値の読み、要求、局所で公開する情報、許す変更を宣言する。
短い式と、束縛・view・構造再帰を使う詳細な定義は、同じ Law の型と評価規則に従う。
`check` は宣言を解決し、明記した内容と版付きの既定規則を確認できる説明を返す。
`run` は問いの選択を解決し、必要な構造を生成して結果と導出元を返す。

Law と問いから決まる意味を、核の計算計画から区別する。
核は必要な計算、算法、内部表現を選び、その条件と出力を検査する。
公開値、量化域、係数、許す変更、名前付き操作の意味を計算計画によって変えない。

本仕様の構文・意味・必須算法・出力を v0.6.0 の実装要件とする。
対応済みの有限計算や整数アフィン計算を常に非対応として返す実装は適合しない。
一般の式も型付きで保持し、未対応な問いをその型・依存・理由とともに返す。

run 一回から回答を読むまでの例は [適合例](validation.md#最小の一周)にある。

## 3. 値、判定、由来

原始値、未観測、明示的な不在、空集合、零を区別する。
観測値を未知の探索変数へ変更せず、許す変更の parameter を候補として計算する。
同じ端点・同じ作用を持つ操作も名前と順序を保持する。

候補写像、configuration の保存、値の保存、object algebra の保存、診断の保存は別の型と検査を持つ。
Law 評価の十分性を、cover・係数・複体を含む診断保存の代用にしない。
障害空間、対象の障害類、局所解の貼り合わせ、許された変更による修復も区別する。

結果には参照した reading、原始入力の版、量化域、成立条件、導出元を保持する。
提案・仕様モデルでの成立を、観測した実装への成立に付け替えない。
前回の結果は同じ Atom 定義・Law・ArchMapから再検査して再利用する。

エンジン自身も、型・構文木・原始変換規則を Atom とし、生成物と独立評価の保存を Law として扱う。
[自己モデルの適合例](validation.md#4-エンジンの有限仕様モデル)はその最小形である。
宣言の解釈、realization・写像・局所状態の生成、その正確性と既存数学の適用条件の確認は
ArchSig の設計・実装・検証責務である。
