# 語彙ルール（vocabulary）

この文書は、`docs/`、`research/`、PR、Issue の文章で使う語彙の決まりを定める。
日本語で書くことと、英語の技術用語をそのまま扱うことは
[Workflow guideline](guideline.md) の「言語」を前提とする。
AAT / Lean の状態語の決まり（「境界」の使用禁止と状態対応表）は
[AAT guideline](../aat/guideline.md) にある。

## 中心規則

使ってよい語は、次の3分類のいずれかに属するものに限る。

1. 一般的な数学用語
2. 一般的なエンジニアリング用語
3. AAT / SFT の独自用語

状態や実体を直接表す平易な語を選び、どの分類にも属さない比喩・物語的な呼び名・内輪の符丁・
遠回しな言い換えは使わない。

## 1. 一般的な数学用語

- 日本語の定着訳がある語は日本語で書く（例: 可換、剰余類、部分群、自然変換）。
- 文献や mathlib で英語のまま流通しており、日本語訳が一意でない語は英語のまま書く
  （例: descent、mate、comparator、site、torsor）。
- 定着訳のある語でも、英語の複合語の中ではそのまま英語で書く
  （例: Čech cohomology、gluing obstruction）。地の文で単独で使うときは定着訳
  （コホモロジー、貼り合わせ）を使う。
- 同じ概念は一つの文書内で表記を統一する。

## 2. 一般的なエンジニアリング用語

- ソフトウェア開発で標準的に通じる語をそのまま使う
  （例: リポジトリ、ビルド、レビュー、キャッシュ、スキーマ）。
- 標準語がある概念は、その標準語をそのまま使う。
- ソフトウェア開発の標準語ではないカタカナビジネス語（例: レバー、
  ネクストアクション）に代えて、平易な日本語で書く。

## 3. AAT / SFT の独自用語

- 使ってよい独自用語は、[AGENTS.md「基礎概念」](../../AGENTS.md) または数学本文
  （[代数幾何的 AAT 数学本文](../aat/algebraic_geometric_theory/README.md) 等）で
  定義済みの語に限る（例: Atom、Law、reading、ArchMap、ArchSig）。
- 新しい独自用語は、定義を追加する変更と同時に導入する。

## 禁止・置換表

次の語は使わず、右の形へ言い換える。
新しい語彙の判断はこの表へ一元的に追記する。
表へ行を追加するときは、grep で誤検知が少ない語に限り、共有反証チェックリスト
§6 の語彙検査パターンも同時に更新する。

| 使わない語 | 書き方 |
| --- | --- |
| 錨、固定錨 | 固定参照（文脈に応じて: 基準、参照点） |
| 正本（所在の指示） | 「X は Y にある」 |
| 正本（優先順位の宣言） | 「Y を正とする」（入口文書・ガイドラインの衝突解決規則としてのみ） |
| 冒頭の「本書は〜の正本である」 | 「本書は〜を定める」 |
| 「本ノートは正本ではない」等の否定形の自己紹介 | 削除し、肯定形の自己紹介と所在への案内を書く |
| 裁定 | 判断 |
| 契約 | 必須項目、検査基準（文脈に応じて） |
| 右サイズ化 | 簡素化 |
| 正枝、負枝 | 成り立つ枝、成り立たない枝（判定結果は「成り立った / 成り立たなかった」） |
| 海域名などの物語装置・比喩の固有名 | 使わない（対象を直接指す）。定義とともに導入した愛称は独自用語として扱う（例: アンナプルナ = Gr 系列の総称、定義は [n1009](../note/n1009_aat_annapurna_gr_series_record.md) §6） |
| 開花、満開（完了段階の呼び名） | 「第一段完了」「全段完了」など、範囲を直接書く |
| 帳簿（簿記の比喩） | 分解、内訳（loop の記録 artifact の既存名「台帳」は対象外） |
| 玩具（toy の直訳） | 最小例、例示スクリプト（定着用語 toy model と既存識別子は対象外） |
| 衛生規則（hygiene の直訳） | 設計規約、構造条件（既存の規律名「足場衛生」は対象外） |
| 湧く（診断・類が「湧く」等） | 生じる |
| 幻 | 偽の類（用語としての phantom は英語のまま） |
| 裏取り | 検算 |
| 地平 | 限界 |
| 押し出し（層の順像 f_* の意味） | 順像（pushout と群拡大の押し出しは標準語として対象外） |
| 「〜を看板にする / しない」（成果の格付け） | 「主要な成果として掲げる / 掲げない」 |
| 安価（成立の自明さの比喩: 「安価経路」等） | 自明な成立、空虚な成立、退化した構成（計算コストの意味は対象外） |

- ファイル名、Lean 識別子、既存の英語識別子（例: `target-goal-contract.md`）、および
  禁止語そのものについて述べる文（この表、レビュー指摘、判断を記録する Issue / PR 本文）は
  そのまま保持する。
- 標準的な技術概念としての contract（API contract、design by contract など）は
  英語表記 `contract` のまま書く。

## 適用範囲

- `docs/` と `research/` の文書、`.codex/skills/` の文書、PR / Issue の本文に
  適用する。
- `outreach/` と `website/` の記事本文・公開文面は [Website guideline](../website/guideline.md) および
  [ブログ執筆ガイドライン](../outreach/guideline.md) の規律に従う。
- 適用対象は新規文書と既存文書への新規追記部分に限る。既存本文への遡及的な一括置換は不要とし、
  完了カード、完了報告、過去のノートはそのまま残す。
