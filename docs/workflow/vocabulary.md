# 語彙ルール(vocabulary)

この文書は、docs / research / PR / Issue の文章で使う語彙の決まりを定める。
日本語で書くこと、英語技術用語をそのまま扱うことは
[Workflow guideline](guideline.md) の「言語」を前提とする。
AAT / Lean の状態語の決まり(「境界」の使用禁止と状態対応表)は
[AAT guideline](../aat/guideline.md) を正とする。

## 中心規則

使ってよい語は、次の3分類のいずれかに属する語だけである。

1. 一般的な数学用語
2. 一般的なエンジニアリング用語
3. AAT / SFT の独自用語

どの分類にも属さない語(比喩、物語装置、会話上の符丁、もって回った言い換え)は
文書に書かない。迷った場合は、状態や実体を直接表す平易な語へ言い換える。

## 1. 一般的な数学用語

- 日本語の定着訳がある語は日本語で書く(例: 可換、剰余類、部分群、自然変換)。
- 文献や mathlib で英語のまま流通し、日本語訳が一意でない語は英語のまま書く
  (例: descent、mate、comparator、site、torsor)。
- 同じ概念には同じ表記を使う。一つの文書の中で訳語と英語を混在させない。

## 2. 一般的なエンジニアリング用語

- ソフトウェア開発で標準的に通じる語をそのまま使う
  (例: リポジトリ、ビルド、レビュー、キャッシュ、スキーマ)。
- 標準語で言える内容に、略語や独自の言い換えを作らない。

## 3. AAT / SFT の独自用語

- 使ってよい独自用語は、[AGENTS.md「基礎概念」](../../AGENTS.md)または数学本文
  ([代数幾何的 AAT 数学本文](../aat/algebraic_geometric_theory/README.md) 等)で
  定義済みの語に限る(例: Atom、Law、reading、ArchMap、ArchSig)。
- 新しい独自用語は、定義の追加と同じ変更でのみ導入する。定義のない新語を
  文書に先に書かない。

## 禁止・置換表

次の語は使わない。左の語を書きそうになったら右の形へ言い換える。
新しい語彙の判断はこの表へ追記し、同じ判断を他の文書へ転記しない。

| 使わない語 | 書き方 |
| --- | --- |
| 錨、固定錨 | 固定参照(文脈に応じて: 基準、参照点) |
| 正本(所在の指示) | 「X は Y にある」 |
| 正本(優先順位の宣言) | 「Y を正とする」(入口文書・guideline の衝突解決規則としてのみ) |
| 冒頭の「本書は〜の正本である」 | 「本書は〜を定める」 |
| 「本ノートは正本ではない」等の否定形の自己紹介 | 削除し、肯定形の自己紹介と所在ポインタ |
| 裁定 | 判断 |
| 契約 | 必須項目、検査基準(文脈に応じて) |
| 右サイズ化 | 簡素化 |
| 正枝、負枝 | 成り立つ枝、成り立たない枝(判定結果は「成り立った / 成り立たなかった」) |
| 海域名などの物語装置・比喩の固有名 | 使わない(対象を直接指す) |

- ファイル名、Lean 識別子、既存の英語識別子(例: `target-goal-contract.md`)は
  置換の対象にしない。

## 適用範囲

- 新規文書と、既存文書への新規追記部分に適用する。
- 既存本文への遡及置換はしない。完了カード、完了 report、過去の note は改変しない。
