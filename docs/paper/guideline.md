# 論文作成ガイドライン

本書は、研究成果を論文として執筆し、検証して公開する工程を定める。
横断規律と保護対象の編集・レビュー・merge 条件は
[Workflow guideline](../workflow/guideline.md) を適用する。

## 配置と責務

- `outreach/paper/<paper-id>/`: 論文ごとの原稿、書誌、図表、証拠対応、公開履歴、固有の処理。
- `outreach/paper/_tools/`: 論文共通のビルド、検査、投稿用 source 作成。
- `docs/paper/arxiv.md`: 確認日・出典付きの投稿先要件。各投稿直前に再確認する。
- `docs/paper/templates/`: 論文ごとの記録を作る雛形。

数学の定義・定理は AAT / SFT の対象文書、形式化は Lean source、計測は固定入力と
出力を参照する。論文の証拠対応表から、それぞれの版と該当箇所へ到達できるようにする。
Lean の状態と検証方法は [AAT guideline](../aat/guideline.md)、実験の検証方法は
対象の分野別 guideline を適用する。

## 品質基準

| 観点 | 達成条件 |
| --- | --- |
| 研究への貢献 | 読者、問い、主要成果、既存研究との差、その意義が具体的に説明されている |
| 数学的な正確さ | 対象、量化、仮定、結論、証明が対応し、依存する結果が特定できる |
| 証拠 | 数学・形式化・計測・観測を区別し、主要な主張と数値が固定された一次証拠に対応する |
| 文献 | 全引用の実在、著者・題名・年・掲載先・識別子、引用内容を原典で確認している |
| 読みやすさ | 初見の想定読者が本文だけで問い、主要成果、その理由と意義を理解でき、用語・記号・図表が一貫している |
| 出版 | 完成 PDF の全文、数式、図表、参照、書誌、metadata を確認している |
| 再現 | 原稿と環境、計測入力、実行手順、期待結果、公開物の版と hash が記録されている |

各論文は、その主張に必要な種類の証拠を揃える。数学・Lean・実験の三要素の有無は
研究課題から決める。SAGA は工程の実例として使い、章数・長さ・三層構成は論文ごとに選ぶ。
新規性の主張は比較した研究と比較軸を具体化する。

## 執筆

読みやすさを論文の品質の必須条件とする。優れた研究成果も、読み手が理解できる形で
伝えて初めて論文として役立つ。想定読者の予備知識を企画時に定め、その読者が本研究や
repo を初めて読む場合にも、本文だけで問い、主要成果、その理由と意義を理解できるように書く。

問題から構成、結果、意義へと説明をつなぎ、必要に応じて具体例や図で理解を助ける。
各節の冒頭で何を説明するかを示し、一文には一つの中心的な主張を置く。
平明で具体的な言葉を使い、専門用語・記号は初出で説明し、同じ概念には同じ用語を使う。

本文には、内容を理解するための定義、主要な仮定、論理のつながり、証明の要点を置く。
仮定は定理の近く、結果の意味を左右する計測条件は結果の近くで説明する。
細かな補足・注釈、査読・監査用の記録、Lean 宣言との対応一覧、実行 ID、再現手順の詳細は
付録にまとめ、必要な箇所から参照する。大きな証拠資料は付録から案内する。

読者向けレビューでは、研究の内部事情を知らない想定読者の立場で本文を通読し、
問い、主要成果、結論に至る筋道、意義を自分の言葉で説明できるか確かめる。
説明が飛ぶ箇所や、細かな注記が理解を妨げる箇所を特定し、修正後に読み直す。

英語版と日本語版を併存させる場合、内容変更は両方へ反映し、定理番号、仮定、数値、
引用の対応を確認する。投稿言語、本文・書誌・図の編集元は論文 README で指定する。

## AI 利用と文献確認

AI の使用ツール、用途、対象範囲、検証方法を `ai-use.md` に記録する。
論文の開示文は実際の利用に合わせ、投稿先が求める重要な利用を記載する。
各著者が最終内容を確認し責任を引き受ける。AI を著者として記載しない。

全参考文献に `references.csv` の行を設ける。原典の公式書誌と本文を開き、書誌情報と
実際に引用する節・ページ・結果を確認してから `verified` にする。DOI の解決だけで
本文の裏付けまで確認済みにしない。確認者、確認日、原典 URL、引用箇所、確認対象の
書誌・原稿の hash を残す。書誌や引用文が変わったら該当行を再確認する。
原典に到達できない行は `pending` とし、別の一次資料を取得するか、その引用を修正する。

定理・数値・図表は対応する証明・入力・出力から確認する。AI による独立レビューも
一次資料との照合を伴わせる。自動検査は未解決引用、仮数値、編集指示、会話文、
欠落ファイルなどの候補を検出する。誤検出は該当箇所と理由を記録して判断する。

## 工程と状態

| 状態 | 次へ進むための記録 |
| --- | --- |
| `planning` | 読者、問い、主要成果、投稿先・種別、既存研究との比較 |
| `drafting` | 章構成、原稿、書誌、図表、主張と証拠の対応 |
| `reviewing` | 固定した原稿一式の hash、内容レビュー、文献全件確認、修正記録 |
| `submission-ready` | 下記の投稿前確認をすべて満たし、人間の著者が最終版を確認 |
| `submitted` | 実際に送った source・PDF・metadata、日時、投稿識別子 |
| `published` | 公開された版・URL・識別子・取得した成果物の hash と公開後確認 |

投稿前確認は `submission.md` に記録する。

1. 投稿先の最新要件と論文種別・投稿資格・license を確認する。
2. 全文献の確認と主要な主張・数値の証拠対応を完了する。
3. 内容の独立レビューと、上記の読者向けレビューを完了し、指摘を解消する。
4. 固定環境でビルドし、未解決引用・参照・文字欠落を解消する。
   行幅超過・余白の警告は位置を確認し、修正または読めることの目視記録を残す。
5. 完成 PDF を全ページ目視し、数式、図表、書誌、ページ欠落、編集指示の残存を確認する。
6. AI 開示、著者・所属・題名・要旨・版・DOI と投稿入力欄の整合を確認する。
7. 人間の著者が投稿する最終版を確認する。arXiv では生成された preview PDF も確認する。

未確認文献、裏付け未確認の主要主張、未解消の内容指摘、未確認の完成 PDF が残る間は
`submission-ready` にしない。検査コマンドの終了コードと投稿可否は別々に記録する。
レビュー後の変更は影響する文献・主張・日英対応・組版を再確認し、対象 hash を更新する。

## 実行手順と検証

共通 CLI のコマンド、環境、出力、検査範囲は
[paper tools](../../outreach/paper/_tools/README.md) にある。
環境の識別は処理系の版、TeX Live 年次、使用資源・OS の記録を含める。
投稿用 source は明示したファイル一覧から作り、展開したディレクトリで再ビルドする。
ローカル執筆用ビルド、投稿先環境の検証、PDF 目視、内容レビューを個別に記録する。

公開時は原稿・投稿用 source・PDF・証拠・metadata の hash と公開識別子を保存する。
公開済み版の tag と成果物を保持し、再生成物には生成元と公開済み版との関係を記載する。
